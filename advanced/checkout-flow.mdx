## Overview

The OrderHub provides a complete checkout flow that converts a cart into an order: create or upsert a cart (with items), preview the checkout to see totals and tax, then complete the checkout with shipping and billing addresses and method IDs. When using the [B2Bware MCP Server](/ai-tools/mcp-server), the tools `upsert_cart`, `preview_checkout`, and `checkout` follow this same flow.

## Flow Diagram

```
1. Create Cart (POST /carts or PATCH /carts for upsert)
       ↓
2. Add Items (POST /cart-items)
       ↓
3. Preview Checkout (GET /carts/{cart}/checkout)
       ↓
4. Complete Checkout (POST /carts/{cart}/checkout)
       ↓
5. Order Created (with line items, addresses, payment)
```

## Step 1: Create a Cart

Create a cart for a known customer or a guest session:

<Tabs>
  <Tab title="Customer Cart" icon="user">
    <Request tabs="cURL">
```bash
curl -s -X POST \
  'https://api.datahub.syncspider.com/api/v1/apps/order-hub/carts' \
  -H 'Authorization: Bearer {token}' \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json' \
  -d '{
    "customer_id": 42,
    "is_active": true,
    "cart_items": [
      {"product_id": 105, "quantity": 2},
      {"product_id": 210, "quantity": 1}
    ]
  }'
```
    </Request>
  </Tab>
  <Tab title="Guest Cart (Upsert)" icon="user-x">

## Step 2: Preview Checkout

Call `GET /carts/{id}/checkout` to calculate totals, shipping costs, and tax without creating the order. Use this to show the customer the final amount before they confirm.

<Request tabs="cURL">
```bash
curl -s -X GET \
  'https://api.datahub.syncspider.com/api/v1/apps/order-hub/carts/17/checkout' \
  -H 'Authorization: Bearer {token}' \
  -H 'Accept: application/json'
```
</Request>

## Step 3: Complete Checkout

Submit the checkout to convert the cart into an order:

<Request tabs="cURL">
```bash
curl -s -X POST \
  'https://api.datahub.syncspider.com/api/v1/apps/order-hub/carts/17/checkout' \
  -H 'Authorization: Bearer {token}' \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json' \
  -d '{
    "shipping_method_id": 1,
    "billing_method_id": 2,
    "shipping_address_id": 15,
    "billing_address_id": 15,
    "comment": "Please gift-wrap the order.",
    "attributes": [
      { "attribute_id": 20, "value": "PO-2026-001" }
    ]
  }'
```
</Request>

## Checkout Validation

| Field | Rules |
|-------|-------|
| `shipping_method_id` | required, numeric |
| `billing_method_id` | required, numeric |
| `shipping_address_id` | required, numeric |
| `billing_address_id` | required, numeric |
| `comment` | string (optional) |
| `attributes` | array, optional — see *Custom Order Attributes* below |
| `attributes.*.attribute_id` | required, numeric — eligible attribute id |
| `attributes.*.value` | mixed — text/number/select label or id |
| `attributes.*.auto_create_value` | boolean, optional |

## Custom Order Attributes (AttributesHub)

Tenants can extend the storefront checkout with their own fields without backend changes:

1. Create an Attribute Group of `type = "order"` in AttributesHub.
2. Add attributes inside that group with `use_in_checkout = true` (toggle on the admin attribute edit page; the switch is visible only when the group is of type `order`).

The storefront flow then becomes:

- `GET /carts/{cart}/checkout` returns an `available_attributes` array. Each entry contains `id`, `attribute_code`, `name`, `type`, `required`, `group`, `values` (only for option-based types `select` / `multiselect` / `radio` / `swatch`; intentionally empty for free-form types so previously-persisted customer answers don't leak between checkouts) and `translation` (when a non-system locale is requested via the `language-code` header). Only attributes where `group.type='order'` AND `use_in_checkout=true` are returned.
- `POST /carts/{cart}/checkout` accepts an `attributes` array of `{attribute_id, value, auto_create_value?}` entries. The same eligibility filter is enforced server-side: ineligible ids yield HTTP 422 (*"The following attribute ids are not available in checkout: {ids}."*), and missing eligible-required attributes yield *"The following required checkout attributes are missing: {codes}."*.

Persisted values are written polymorphically against the resulting Order (`attributable_type=Apps\OrderHub\Models\Orders`, `attributable_id={order.id}`). Read them back with `?include=attributeValues,attributeValues.value,attributeValues.value.attribute` on order detail endpoints.

## Loading Cart with Full Product Data

Use includes to get complete product information for cart display:

<Request tabs="cURL">
```bash
curl -s -X GET \
  'https://api.datahub.syncspider.com/api/v1/apps/order-hub/carts/17?include=cartItems.product.price,cartItems.product.finalPrice,cartItems.product.mainMedia,cartItems.product.crossSells,customer' \
  -H 'Authorization: Bearer {token}' \
  -H 'Accept: application/json'
```
</Request>
