## Overview

The StorefrontBuilderHub powers the visual builder in the b2bware admin. It stores page, document, email, and theme-slot content as validated builder JSON and renders that content for previews and storefront delivery. Its public API surface also covers **Documents** — print-ready designs such as catalogs and price lists built from your live product data — and **Generated PDFs**, the exports produced from those documents.

A document can render in two modes: one PDF per record (e.g. a per-product datasheet) or a single catalog-style PDF over an entire record set (e.g. a grouped price list with a table of contents and page numbers). Documents support data tables with column formatting, category or value grouping, and repeatable header/footer regions.

PDF export is asynchronous: you queue an export, poll its status, and download the finished file. Every export moves through a defined status lifecycle and keeps its history in the Generated PDFs list.

**Base URL:** `api/v1/apps/storefront-builder-hub/`

<Callout kind="info">
All endpoints require Bearer token authentication plus admin access, and mutations enforce the matching StorefrontBuilderHub permission. See [Authentication](/authentication).
For filter syntax, pagination, and sorting, see [Common Patterns](/core-concepts/common-patterns).
</Callout>

## Export Status Lifecycle

Every export reports one of the following statuses:

| Status | Meaning |
|--------|---------|
| `queued` | The export is waiting for a worker |
| `processing` | The PDF is being rendered; `progress` reports 0–100 |
| `completed` | The PDF is ready to download |
| `failed` | Rendering failed; the export carries an error reference |
| `cancelled` | The export was cancelled before completion |

`completed`, `failed`, and `cancelled` are final — an export never leaves a final status. A failed or cancelled export stores no PDF file.

## Reusable section library

The section library stores one detached builder `section` node plus the data sources that section references. Saved sections belong to the current installation. Curated read-only sections provided by the platform can appear alongside your own.

- Saved records carry the current `installation_key`.
- Platform-provided sections are read-only: they can be inserted, but not edited or deleted.
- Inserting a section creates a detached copy; later library edits do not change pages that already use it.
- Thumbnail generation is asynchronous and writes the resulting image through MediaHub.

Library records are bounded to 256 KiB, 200 nodes, and 10 data sources.

## Global page context

Every storefront page can bind to curated `context` roots for the signed-in customer (`me`), store, cart summary, normalized cart items, visitor capabilities, and locale/currency. A root is resolved only when the document references its declared source, so unused customer, cart, and store context does not add render work. Context-dependent output is never stored in the shared guest HTML cache.

## Page previews and authored SEO

Page SEO and access settings live inside `content_json`. Authored SEO supports standard metadata, Open Graph fields, robots flags, and bounded JSON-LD.

## Permissions

Document and export endpoints are guarded by granular permissions in addition to admin access:

| Permission | Grants |
|------------|--------|
| `storefront-builder-hub.documents.view` | List/read documents, templates, dataset counts |
| `storefront-builder-hub.documents.create` | Create documents |
| `storefront-builder-hub.documents.update` | Update documents |
| `storefront-builder-hub.documents.delete` | Delete documents |
| `storefront-builder-hub.generated-pdfs.view` | List/read exports and export status |
| `storefront-builder-hub.generated-pdfs.create` | Queue PDF exports |
| `storefront-builder-hub.generated-pdfs.download` | Download completed PDFs |
| `storefront-builder-hub.generated-pdfs.delete` | Delete exports |
