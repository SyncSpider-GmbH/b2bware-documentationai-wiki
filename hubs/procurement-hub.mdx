## Overview

ProcurementHub is the admin API for suppliers, purchasing, receiving, and
accounts-payable vendor bills. Vendor bills support manual creation or PDF-first
capture with immutable source media, field provenance, manual correction audit,
and optional matching to a purchase order.

**Base URL:** `api/v1/apps/procurement-hub/`

<Callout kind="info" title="Admin API">
All endpoints require admin access and the matching ProcurementHub permission.
</Callout>

## Available Actions

Document workspaces use the `available-actions` responses instead of deriving
buttons from status on the client. Purchase orders expose `edit`, `approve`,
`send`, and `receive` only in valid lifecycle states. Vendor bills expose
`edit` and `match` while review is allowed; paid and cancelled bills return no
actions.

## Manual and PDF-First Capture

`POST /vendor-bills` creates a manual bill. It can reference an existing
MediaHub PDF with `pdf_media_id` or accept a `pdf_media` descriptor containing
`public_url`, optional `id`, `file_name`, `mime_type`, and `size`.

`POST /vendor-bills/capture` requires either `pdf_media_id` or `pdf_media`.
The source PDF is linked with document role `source`, version `1`, and immutable
metadata. If AiHub is available, extraction reads embedded text first and falls
back to rendered-page vision. An unavailable or unreliable extractor leaves the
bill in manual review instead of inventing values.

## Extraction and Corrections

Extraction stores separate raw, normalized, and review state:

| Field | Meaning |
|---|---|
| `extraction_raw` | Provider/mode response and diagnostics |
| `extraction_parsed` | Normalized business values |
| `extraction_status` | `not_requested`, `pending_manual`, `manual_review`, `completed_ai`, or `completed_manual` |
| `extraction_provenance` | Per-field page, normalized bbox, source text, alternatives, confidence, mode/version, and corrections |
| `corrected_fields` | Latest manually corrected values |
| `correction_audit` | Append-only original/previous/corrected values, timestamp, actor, and source |

Corrections are submitted as `{ "fields": { ... }, "complete": true|false }`.
Only the supported vendor-bill fields are applied. Correcting line items
normalizes their values and recomputes missing totals. The audit preserves the
first original value across repeated corrections.

## Reference Integrity and Department Visibility

Supplier, purchase-order, and product references must resolve in the current
installation. Optional ProductHub references are checked lazily, so custom
purchase-order and vendor-bill lines remain valid without a product link.

Purchase orders and vendor bills store `department_ids`. Goods receipts inherit
the assignments from their purchase order. Users who have only own-department
accounting-report access see documents that overlap their assigned departments;
no assigned department fails closed. Full accounting-report access bypasses the
restriction.

## Contact Matching and Snapshots

Vendor bills retain `supplier_id` compatibility and can also reference
`contact_id`, `commercial_contact_id`, and `representative_contact_id`.
Canonical contact data is preferred for counterparty resolution; legacy
suppliers remain the fallback. CustomerHub's supplier profile is enabled
idempotently and can retain `legacy_supplier_id`.

At creation, ProcurementHub captures immutable `counterparty_snapshot`,
`billing_address_snapshot`, `shipping_address_snapshot`, and `snapshot_source`.
Later supplier/contact changes do not rewrite historical documents.

## PDF Projection

When a linked PDF exists, the vendor-bill detail response also exposes
`pdf_url` and:

```json
{
  "pdf": {
    "id": 100,
    "public_url": "https://cdn.example.com/vendor-bills/100.pdf",
    "file_name": "vendor-bill.pdf",
    "mime_type": "application/pdf"
  }
}
```
