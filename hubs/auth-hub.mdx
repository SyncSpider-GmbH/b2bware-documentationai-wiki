## Overview

AuthHub issues and manages user sessions. It is the entry point for storefront customers (login, register, forgot password, verify email) and for sales agents who impersonate a customer to place orders on their behalf.

**Base URL:** `api/v1/apps/auth-hub/`

<Callout kind="info">
The storefront entry flows — `login`, `register`, `forgot-password`, `reset-password`, and `verify-email` — are public: they need only the installation key (in the header, or in the URL for the email-link flows), because the user is not logged in yet. Session, impersonation, and admin endpoints sit behind `auth:api`.
</Callout>

## Endpoints

<Tabs>
  <Tab title="Session" icon="key">

| Method | Endpoint | Auth | Description |
|---|---|---|---|
| POST | `/login` | installation key | Exchange credentials for a personal access token. |
| POST | `/register` | installation key | Create a new customer account. |
| POST | `/logout` | `auth:api` | Revoke the current token. |
| GET  | `/me` | `auth:api` | Return the authenticated user with roles and customer profile. |

  </Tab>
  <Tab title="Password & Email" icon="envelope">

| Method | Endpoint | Auth | Description |
|---|---|---|---|
| POST | `/forgot-password` | installation key | Send a password-reset email. |
| POST | `/{installationKey}/reset-password` | installation key | Complete a password reset using the token from the email. |
| POST | `/send-verification-email` | `auth:api` | (Re)send the address-verification email. |
| POST | `/{installationKey}/verify-email` | installation key | Mark the email as verified using the token from the email. |

  </Tab>
  <Tab title="Admin email change" icon="user-gear">

Admin-panel endpoints (B2BWare → Customer Details → Security) to change a customer's email by ID, without the customer's password. They require admin authentication (`auth:api`); the installation key is resolved from the customer automatically. On success the new address receives a 6-digit verification code, and confirming it forces the customer to re-login.

| Method | Endpoint | Auth | Description |
|---|---|---|---|
| POST   | `/admin/customer/{customerId}/request-email-change` | `auth:api` | Start an email change and send a verification code to the new address. |
| GET    | `/admin/customer/{customerId}/pending-email-change` | `auth:api` | Return the customer's pending (unverified) email change, if any. |
| POST   | `/admin/customer/{customerId}/verify-email-change` | `auth:api` | Confirm the change with the 6-digit code. |
| DELETE | `/admin/customer/{customerId}/cancel-email-change` | `auth:api` | Revoke any pending email change. |

  </Tab>
  <Tab title="Impersonation" icon="user-secret">

Used by sales agents to act on behalf of a specific customer (cart, checkout, order history all become that customer's).

| Method | Endpoint | Auth | Description |
|---|---|---|---|
| GET  | `/impersonate/customers` | `auth:api` | List customers the agent is allowed to impersonate. |
| POST | `/impersonate/{customerId}` | `auth:api` | Start impersonating the given customer. |
| POST | `/impersonate/leave` | `auth:api` | Stop impersonating and return to the agent's own session. |

  </Tab>
</Tabs>
