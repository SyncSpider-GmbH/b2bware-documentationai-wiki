## Overview

IntegrationHub connects DataHub to external platforms (WooCommerce, Shopify, Walmart, FTP file feeds, and more). Operators configure integrations in the B2Bware admin (or an [embedded iframe](/help-center/guides/embed-integration-hub)); workers on the `integration-sync` queue import and export data through field mappings and blueprints.

**Base URL:** `api/v1/apps/integration-hub/`

<Callout kind="info">
Most routes require Bearer `auth:api` plus a `permission:integration-hub.*` key. Public exceptions: OAuth callback / app-login and `POST embed/bootstrap` + `POST embed/refresh` (throttled). Pagination follows [Common Patterns](/core-concepts/common-patterns) (`per_page`, flat `data` / `total` / `current_page` / `total_pages`).
</Callout>

Operator walkthrough: [Integration Hub guide](/help-center/guides/integration-hub). There is no published OpenAPI collection for this hub yet; use the tables below as the endpoint map.

## Architecture

| Store | What lives there |
|---|---|
| **MySQL** | `integrations`, `integration_entities`, `integration_field_mappings`, `sync_runs`, `integration_relay_routes`, hub settings |
| **MongoDB** | `sync_logs_{integration_id}`, `integration_responses_{integration_id}`, Hub records in `items_{entity_id}` |
| **Redis / Horizon** | Queue `integration-sync` (import, export, relay jobs) |

```
Connector package (Integrations/*)
  → ConnectorRegistry
  → SyncService → ImportSyncJob / ExportSyncJob
  → TransformService (+ optional RelayForwardJob)
  → Mongo items_* / sync_logs_* / integration_responses_*
```

### Jobs

| Job | Purpose |
|---|---|
| `ImportSyncJob` | Pull from connector → write Hub items |
| `ExportSyncJob` | Read Hub items → push to connector; capture response JSON |
| `RelayForwardJob` | Map captured export response → push to another integration |

## Auth and embed

| Mode | How identity works |
|---|---|
| Admin / API token | `auth:api` → installation SpiderDesk user; Gate grants admin for Desk users |
| Embed session | Host bootstraps with public token or partner JWT; subsequent calls send `X-IH-Embed-Token`. Permissions are an allow-list (`EmbedOperator`); Desk admin bypass is suppressed when that header is present. `Auth::user()` remains the installation Desk user for company scoping (SpiderDeskGuard is not overridden). |

See [Embed Integration Hub](/help-center/guides/embed-integration-hub).

## Core concepts

| Concept | Description |
|---|---|
| **Integration** | Top-level connection: connector type, credentials / OAuth state, status, schedule |
| **Entity** | One source ↔ target pair with direction (inbound / outbound), decisions, filters |
| **Field mapping** | Source path → target field + transform pipeline |
| **Blueprint** | Connector-provided defaults, decision questions, discovery helpers |
| **SyncRun** | One execution with counters (+ optional `relay_stats`) |
| **SyncLog** | Per-record audit in Mongo |
| **Relay route** | After export success, map captured response into another integration |

## Transform types

`TransformService` pipelines (chainable):

| Type | Role |
|---|---|
| `direct`, `cast`, `map`, `format`, `expression`, `round` | Value shaping |
| `replace`, `prefix`, `suffix`, `substring` | String ops |
| `lowercase`, `uppercase`, `default`, `conditional` | Normalise / branch |
| `custom`, `ai` | Extension / external AI |

## Response Relay flow

1. **Capture** — export upserts connector JSON into `integration_responses_{integration_id}`.
2. **Routes** — MySQL `integration_relay_routes` (mapping, filter, optional `match_config`, `on_export_success`).
3. **Forward** — `RelayForwardJob` maps, matches remote id, `pushEntity`, optional multi-hop (max 5).
4. **Observe** — `sync_runs.relay_stats` on Sync Run Detail.

## Adding a connector (high level)

1. Add `packages/Integrations/{Vendor}/` with a class extending `AbstractConnector`.
2. Register it on `ConnectorRegistry` from the package service provider.
3. Wire composer autoload + provider in the root app.

Full PHP recipe, OAuth helpers, Horizon concurrency, and sync-progress semantics live in the package developer guide under `packages/Utility/IntegrationHub/docs/developer-guide.md` (internal DataHub repo). Use the IntegrationHub connector skill when scaffolding a new vendor package.
