## Overview

AccountingHub provides operational accounting reports and bank reconciliation
for InvoiceHub and ProcurementHub documents. Version 1 is deliberately
**reports-only**: it does not create journal entries, a chart of accounts, a
general ledger, or double-entry postings.

**Base URL:** `api/v1/apps/accounting-hub/`

<Callout kind="info" title="Admin API">
All endpoints require admin access and the endpoint-specific AccountingHub
permission. Send the tenant `installation-key` and bearer credentials expected
by your DataHub installation.
</Callout>

Import returns HTTP `202` with `{"message":"Bank transaction import queued"}`.
The queued job restores the tenant from the installation key before accessing
provider or accounting data.

<Callout kind="warning" title="Bank-account deletion dependencies">
`DELETE /bank-accounts/{id}` returns HTTP `409` while the account has bank
statements, bank transactions, or reconciliations. The body contains
`message` and a `dependencies` array naming every blocker. Remove or retain
those dependent records according to your retention policy before retrying.
</Callout>

  <Tab title="Reconciliation">

| Method | Endpoint | Permission | Description |
|---|---|---|---|
| GET | `/reconciliations` | `accounting-hub.reconciliation.perform` | List reconciliation records. |
| GET | `/bank-transactions/{bankTransaction}/suggestions` | `accounting-hub.reconciliation.perform` | Suggest open invoices or vendor bills by amount, currency, and reference. |
| POST | `/bank-transactions/{bankTransaction}/match` | `accounting-hub.reconciliation.perform` | Match one transaction to an invoice or vendor bill. |

Match input requires `document_type` (`invoice` or `vendor_bill`) and
`document_id`. Optional fields are `matched_amount`, `match_method` (`manual`
or `automatic`), and `confidence` from `0` to `1`.

Matching is resumable and idempotent per bank transaction. Retrying the same
transaction/document pair resumes any missing transaction, document, status,
or completion-event side effect and returns the existing reconciliation.
Completion progress is persisted in reconciliation metadata. A retry does not
allocate the payment twice or emit a second completion event. Attempting to
reuse that transaction for a different document is rejected.

Only open documents with the same currency can be matched, and the matched
amount must equal the open document amount within the configured tolerance.

## Pagination, Filtering, and Sorting

Department, bank-account, statement, transaction, and reconciliation list
endpoints accept `page` (minimum `1`) and `per_page` (minimum `1`, maximum
`200`, default `25`). Their response is flat:

```json
{
  "data": [],
  "total": 0,
  "current_page": 1,
  "total_pages": 1,
  "per_page": 25
}
```

Supported filters are `id`, `status`, `bank_account_id`, `department_id`,
`name`, `code`, and `reference`. Supported sorts are `id`, `name`, `code`,
`booking_date`, `amount`, `status`, and `_created_at`; the default is
descending `id`.

## Error Contract

| Status | Meaning |
|---|---|
| `401` | Missing or invalid authentication. |
| `403` | Missing AccountingHub permission or no assigned department access. |
| `404` | Accounting resource or source document not found. |
| `409` | Bank-account deletion has dependencies. |
| `422` | Validation failed; the response contains field-level errors. |
| `500` | Provider, tenant-context, or reconciliation processing failed. |
