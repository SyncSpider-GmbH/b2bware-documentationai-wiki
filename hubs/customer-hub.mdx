## Overview

The CustomerHub manages customers, companies, addresses, roles, customer groups, and notes. It integrates with AttributesHub for custom customer and company attributes and provides a settings system via HubSettingsTrait.

**Base URL:** `api/v1/apps/customer-hub/`

<Callout kind="info">
All endpoints require Bearer token authentication. See [Authentication](/authentication).
For filter syntax, pagination, and sorting, see [Common Patterns](/core-concepts/common-patterns).
</Callout>

## Endpoints

<Tabs>
  <Tab title="Contacts" icon="contact">

Canonical company and person identities. A contact is a commercial identity,
not an authentication principal. Existing customer, company, billing-address,
and shipping-address IDs and APIs remain authoritative compatibility surfaces
during the additive migration.

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/contacts` | List contacts with flat `per_page` pagination |
| POST | `/contacts` | Create a company or person contact |
| GET | `/contacts/{id}` | Get the complete contact detail projection |
| PUT | `/contacts/{id}` | Update contact identity fields |
| DELETE | `/contacts/{id}` | Delete a contact |
| POST | `/contacts/{id}/profiles/customer` | Idempotently enable the customer profile |
| POST | `/contacts/{id}/profiles/supplier` | Idempotently enable the optional ProcurementHub supplier profile |

Contact creation never creates a user account and never silently merges
matching contacts. A person-to-company affiliation does not grant
authorization; only a `company_membership` attached to a user account does.
Profile enablement is idempotent.

List filters are accepted either inside `filter` or as top-level compatibility
parameters: `search`, `kind`, `profile`, `status`, and `profile_priority`.
`per_page` is capped at 100. Include aliases may be camelCase, while response
keys are consistently snake_case.

The detail projection can expose identifiers, company/person affiliations,
`user_account`, authorization `memberships`, canonical addresses,
`customer_profile`, optional ProcurementHub `supplier_profile`, legacy IDs, and
smart-action counts. `legacy_customer_id`, `legacy_company_id`, and
`legacy_supplier_id` let integrations correlate canonical contacts without
changing existing integer identifiers.

  <Tab title="Favorites" icon="heart">

Per-customer wishlist. The favorites payload is stored as a single record on the customer and supports multiple named lists with an `active_list_id` pointer.

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/favorites` | Get the current customer's favorites state |
| PUT | `/favorites` | Replace the current customer's favorites state (idempotent) |

The PUT body is normalized server-side to:

```json
{
  "lists": [
    {
      "id": "<uuid>",
      "name": "My wishlist",
      "items": [
        { "id": 105, "name": "...", "sku": "...", "slug": "...", "price": 29.99, "image_url": "...", "added_at": "ISO8601", "quantity": 1 }
      ],
      "created_at": "ISO8601",
      "updated_at": "ISO8601"
    }
  ],
  "active_list_id": "<uuid>"
}
```

Authentication is by `x-auth-token` (shop guard). A customer can only read or write their own favorites.

  <Tab title="Dashboard" icon="bar-chart">

Read-only aggregates over CustomerHub data. Used by DashboardHub widgets but stay enabled even when DashboardHub is absent.

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/dashboard/customers-overview` | Totals + verified-email count + period-over-period delta |
| GET | `/dashboard/customer-growth` | Daily new-customer series (optionally with a companies series) |
| GET | `/dashboard/top-customer-groups` | Top N customer groups by member count, plus ungrouped count |
| GET | `/dashboard/recent-signups` | N most-recent customers with name, email, company and verification flag |
| GET | `/dashboard/verification-funnel` | Email / phone / both verified counts and percentages |

All dashboard endpoints accept a `period` query parameter — one of `7`, `30`, `90`, `365` (defaults to `30`) where applicable.

integrations. The canonical Contacts API is additive; legacy maps and projected
legacy IDs provide the migration bridge.
</Callout>

## Examples

<Steps>
  <Step title="Search customers with includes">
    <Request tabs="cURL">
```bash
curl -s -X GET \
  'https://api.datahub.syncspider.com/api/v1/apps/customer-hub/customers?filter[search]=john&include=company,role,customerGroup&per_page=20&sort=-_created_at' \
  -H 'Authorization: Bearer {token}' \
  -H 'Accept: application/json'
```
    </Request>
  </Step>
  <Step title="Filter customers by company name">
    <Request tabs="cURL">
```bash
curl -s -X GET \
  'https://api.datahub.syncspider.com/api/v1/apps/customer-hub/customers?filter[company.name]=[{"condition":"LIKE","value":"%Acme%"}]&include=company,shippingAddresses,billingAddresses' \
  -H 'Authorization: Bearer {token}' \
  -H 'Accept: application/json'
```
    </Request>
  </Step>
  <Step title="Create a customer with attributes">
    <Request tabs="cURL">
```bash
curl -s -X POST \
  'https://api.datahub.syncspider.com/api/v1/apps/customer-hub/customers' \
  -H 'Authorization: Bearer {token}' \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json' \
  -d '{
    "first_name": "John",
    "last_name": "Doe",
    "email": "john.doe@example.com",
    "phone": "+1234567890",
    "salutation": "Mr.",
    "status": "active",
    "password": "securePassword123",
    "company_id": 1,
    "role_id": 2,
    "customer_group_id": 1,
    "attributes": [
      {"attribute_value_id": 10},
      {"attribute_value_id": 25}
    ]
  }'
```
    </Request>
  </Step>
  <Step title="Filter companies with VAT number">
    <Request tabs="cURL">
```bash
curl -s -X GET \
  'https://api.datahub.syncspider.com/api/v1/apps/customer-hub/companies?filter[vat_number]=[{"condition":"NOT EMPTY"}]&include=customers,shippingAddresses,billingAddresses&sort=name' \
  -H 'Authorization: Bearer {token}' \
  -H 'Accept: application/json'
```
    </Request>
  </Step>
  <Step title="Filter customers by date range">
    <Request tabs="cURL">
```bash
curl -s -X GET \
  'https://api.datahub.syncspider.com/api/v1/apps/customer-hub/customers?filter[_created_at]=[{"condition":">=","value":"2024-01-01"},{"condition":"<=","value":"2024-06-30","operator":"AND"}]&per_page=50&sort=-_created_at' \
  -H 'Authorization: Bearer {token}' \
  -H 'Accept: application/json'
```
    </Request>
  </Step>
</Steps>
