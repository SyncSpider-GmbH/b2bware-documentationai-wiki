## Overview

InvoiceHub is the admin API for invoices and credit notes. It owns document
numbering, totals, lifecycle transitions, capture-time counterparty and address
snapshots, and outgoing PDF generation.

**Base URL:** `api/v1/apps/invoice-hub/`

<Callout kind="info" title="Admin API">
All endpoints require admin access and the matching InvoiceHub permission.
Snapshots and generated document metadata are server-controlled after creation.
</Callout>

The available-actions endpoints return an `actions` array. Admin clients use it
to render only valid lifecycle controls instead of offering arbitrary status
changes that the service would reject.

## Reference Integrity and Department Visibility

Non-null `source_order_id`, `invoice_id`, and line-item `product_id` values must
resolve in the current installation. Optional source hubs are checked lazily, so
manual documents remain available when OrderHub or ProductHub is not installed.

Selecting a source order creates a durable association through `source_order_id`
and copies the customer, company, product lines, billing and shipping addresses,
payment method, and shipping method into the invoice draft. These copied values
remain editable while the invoice is a draft; changing the invoice does not
rewrite the source order.

Selecting an invoice for a credit note creates a durable association through
`invoice_id` and preloads the invoice customer/contact references, immutable
counterparty and address snapshots, departments, currency, source-order
reference, and product lines. The resulting credit-note draft remains editable.
For direct API creation, the service applies these values as defaults when they
are omitted; explicitly supplied fields and `line_items` take precedence.

Users with full accounting-report access can read all documents. Users who have
only own-department report access can read invoices and credit notes whose
`department_ids` overlap their assigned departments; no assigned department
fails closed.

## Immutable Counterparty Snapshots

Creation retains compatibility references such as `customer_id`, `company_id`,
`contact_id`, `commercial_contact_id`, and `representative_contact_id`, but also
captures historical values into:

- `counterparty_snapshot`
- `billing_address_snapshot`
- `shipping_address_snapshot`
- `payment_method_snapshot`
- `shipping_method_snapshot`
- `snapshot_source` (`capture_time`; explicit migrations may use `backfill_live`)

Canonical contacts are preferred when contact IDs are supplied; legacy customer
and company references remain supported. A supplied snapshot is normalized at
capture time. Later contact, customer, company, or address changes do not rewrite
the stored document snapshot, and snapshot fields are prohibited on update.
Payment and shipping method snapshots are intentionally editable on draft
invoices and are included in the generated PDF.

## Invoice Custom Attributes

InvoiceHub registers the `invoice` group type in AttributesHub. Attribute
definitions assigned to a group of this type can be attached to invoices through
the `attributes` request field:

```json
{
  "attributes": [
    {
      "attribute_id": 42,
      "value": "Project A",
      "auto_create_value": true
    }
  ]
}
```

Invoice responses include the resolved `attribute_values` relation. Sending a
`null` value removes the corresponding assignment. Credit notes do not currently
expose a separate attribute group type.

## Generated PDF Lifecycle

Draft documents can generate a PDF preview without changing lifecycle status
through the `preview-pdf` endpoints. The admin requests this preview after a
draft is saved and when an existing editable document has no generated PDF.
Sending an invoice or issuing a credit note still ensures that the current PDF
exists before the lifecycle transition. The effective document content plus
renderer version produces a SHA-256 content hash:

- retrying unchanged content reuses the existing generated version;
- changed effective content creates the next version;
- previous generated versions are retained;
- finalized invoices and issued credit notes, including their PDF versions,
  cannot be deleted through these endpoints.

Invoice and credit-note responses project:

| Field | Meaning |
|---|---|
| `pdf_media_id` | Compatibility pointer to the current generated PDF |
| `generated_pdf` | Latest generated version, or `null` |
| `document_media_versions` | All linked source/generated document versions |
| `layout_provenance` | Renderer/layout metadata stored with the document |

Each `document_media_versions` entry can include `media_id`, `role`, `version`,
`immutable`, `content_hash`, `url`, `file`, `renderer_version`, `generated_at`,
`installation_key`, `document_type`, and `document_id`.
