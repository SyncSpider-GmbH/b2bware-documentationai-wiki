## What are hub settings?

Most hubs expose **App Settings**: installation-scoped configuration edited in the admin under each hub’s **Settings** screen, and via that hub’s `/settings` HTTP API (`GET/POST /api/v1/apps/<hub>/settings`, per-group routes, and reset where supported).

Settings are organized into **groups** (for example ProductHub `stock`, `visibility`, `pricing`). Each group contains typed fields (boolean, number, select, text, nested objects). Values apply to the current installation (tenant), not globally across all companies.

<Callout kind="info">
Per-hub **field references** (key, type, default, behavior) live on each [hub page](/hubs/overview) under **Settings** / **Settings Groups**. This page is the index.
</Callout>

## Settings vs SettingsHub

| Concept | Where | Purpose |
|---------|-------|---------|
| **Hub App Settings** | Each hub’s `/settings` + admin App Settings | Domain behavior (stock defaults, notifications, tax calculation, …) |
| **SettingsHub** | `settings-hub` | Platform config: locales, translations, cache, indexing, and **currency / i18n** (`global_config.value.i18n`) |

See [SettingsHub](/hubs/settings-hub) for currency keys; see each hub below for App Settings groups.

## API pattern

Typical endpoints (exact paths vary slightly by hub):

| Method | Path | Purpose |
|--------|------|---------|
| `GET` | `/api/v1/apps/<hub>/settings` | Schema + values (+ defaults when exposed) |
| `GET` | `/api/v1/apps/<hub>/settings/{group}` | One group |
| `POST` | `/api/v1/apps/<hub>/settings` | Save one or more groups |
| `POST` | `/api/v1/apps/<hub>/settings/{group}` | Save one group |
| `POST` | `/api/v1/apps/<hub>/settings/reset` | Reset to defaults (when supported) |

Authentication and permissions follow each hub’s admin API rules. Secrets (SMTP passwords, API keys, signing secrets) may be **masked** on read.
