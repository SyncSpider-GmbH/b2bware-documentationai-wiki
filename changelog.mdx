<Update label="2026-08-24" description="MCP Server: sign in with B2Bware" tags={["feature", "security"]}>

## Sign in with B2Bware, instead of pasting a key

The MCP Server is now hosted by B2Bware itself and supports **browser sign-in**. Point your client at `https://mcp.b2bware.com/mcp` with no key and no headers, and it takes you through a B2Bware login — the same shape as connecting GitHub to an editor.

- **Nothing secret in your config**, so it is safe to commit and share. Each person signs in as themselves.
- **Connect several B2Bware accounts** and choose per request which one a call applies to.
- **Your own permissions, re-checked on every call** by the same code that answers the admin panel. No MCP-specific permission model.
- **Revoke from Developers → MCP Server**, effective on the next request. Access also ends by itself when an account is removed, company access is withdrawn, or a company is deactivated.
- Signing in currently exposes **6 read-only tools**. An **API key still gives the full 163-tool surface** including writes and bulk operations, and remains supported — see [MCP Server](/ai-tools/mcp-server).

## Storefront assistant for your customers

Buyers in your shop can connect their own assistant to their own account — **20 tools** covering catalog search at their prices, their own and their company's order history, reorder, their addresses, cart, and checkout. Off by default; enable per shop in **Developers → MCP Server**. Optionally served on your own domain.

## Deprecated: API keys in the URL

`?key=…` is deprecated and **stops working on 1 November 2026**. A key that has appeared in a URL has been in proxy logs, browser history and `Referer` headers — move to the `Authorization` header **and rotate the key**. Relocating it does not undo the exposure.

</Update>

## Parent category products on the storefront

- **Store default** — `tenant_config.categories.branch_display_mode`: `children` (default), `products`, or `both`. Surfaced to themes as `$store['branch_display_mode']`.
- **Per-category override** — ProductHub `Category.branch_display_mode` (`null` = inherit). Admin: Category → General and Store setup → Features.
- **Theme contract** — category pages expose `$branchDisplayMode`, `$showChildren`, `$showProducts`. Branch product listings use `anchor_category_id` (category + descendants). See [Catalog](/advanced/storefront-themes/catalog) and [View data](/advanced/storefront-themes/view-data).

</Update>

<Update label="2026-06-03" description="Custom Order attributes on checkout" tags={["feature"]}>

## OrderHub × AttributesHub — custom Order attributes on storefront checkout

Tenants can now extend the OrderHub storefront checkout with their own fields without backend changes — purchase order numbers, internal notes, delivery preferences, anything modeled as an AttributesHub attribute.

### How it works

1. Create an Attribute Group of `type = "order"` in AttributesHub.
2. Add attributes inside that group and toggle the new **Use in Checkout** switch (visible on the admin attribute edit page only when the group is of type `order`).
3. The storefront automatically picks them up:
   - `GET /api/v1/apps/order-hub/carts/{cart}/checkout` returns an `available_attributes` array (id, code, name, type, required, group, values, translation) — only attributes with `group.type='order'` AND `use_in_checkout=true`.
   - `POST /api/v1/apps/order-hub/carts/{cart}/checkout` accepts an `attributes` array of `{attribute_id, value, auto_create_value?}` entries; ineligible or missing-required ids return HTTP 422 with explicit messages.

### Persistence

Submitted values are stored polymorphically against the resulting Order (`attributable_type=Apps\OrderHub\Models\Orders`, `attributable_id={order.id}`). Read them back with `?include=attributeValues,attributeValues.value,attributeValues.value.attribute` on order detail endpoints, or via the `$order->{attribute_code}` magic getter.

### Filters

`Attribute` is now filterable by `use_in_checkout` and `use_in_notifications` (in addition to the existing visibility / filtering flags).

See [OrderHub → Checkout flow](/advanced/checkout-flow), [OrderHub hub page](/hubs/order-hub), and [AttributesHub hub page](/hubs/attributes-hub) for the complete contract.

</Update>
