## B2Bware MCP Server

The B2Bware MCP Server connects AI assistants to your live DataHub using the [Model Context Protocol (MCP)](https://modelcontextprotocol.io). It is hosted by B2Bware — nothing to install, nothing to run.

**Server URL:** `https://mcp.b2bware.com/mcp`

<Callout kind="info" title="What is MCP?">
The Model Context Protocol (MCP) is an open standard that lets AI assistants call external tools and read live data. With B2Bware connected, your assistant can browse the catalog, look up orders and customers, build carts and complete checkout — in conversation, against your real data.
</Callout>

## Two ways to connect

Both are supported, and both stay supported. They are not two routes to the same place, so pick on what you are doing rather than on which looks newer.

| | Sign in with B2Bware | API key |
| --- | --- | --- |
| How you authenticate | Browser sign-in, like connecting GitHub to an editor | Paste a key into your client's config |
| What it is for | A person using an assistant | Server-to-server, scripts, integrations |
| Tools available | **6**, read-only (catalog, orders, customers) | **163**, including writes and bulk operations |
| Multiple B2Bware accounts | Yes — pick which ones to connect, switch per request | One key, one tenant |
| Permissions | Exactly what your own B2Bware login can do | Whatever the key was issued for |
| Revoking access | **Developers → MCP Server** in admin, takes effect immediately | Rotate the key |

<Callout kind="alert" title="Read this before choosing">
Signing in gives you **6 read-only tools today**. If you need to create products, sync stock, or place orders from your assistant, you need an **API key** — the sign-in path does not expose write tools yet. The two surfaces are converging, but they are not equivalent right now.
</Callout>

## Deprecations

| What | Status | Stops working |
| --- | --- | --- |
| **API key in the URL** (`?key=…`) | Deprecated | **1 November 2026** |
| `npx b2bware-mcp` (local install from npm) | No longer published; versions up to `1.14.0` stay installable | No date — but it gets no new tools |
| `/sse` endpoint (legacy transport) | Supported for existing clients | No date announced |

<Callout kind="alert" title="If your key is in a URL, treat it as leaked">
A key in a query string ends up in proxy logs, browser history and `Referer` headers. Move to the `Authorization` header, then **rotate the key** — moving it alone does not undo the exposure. After 1 November 2026 requests carrying `?key=` are refused with `QUERY_KEY_DISABLED`.
</Callout>

Clients that support **MCP prompts** can fetch curated playbooks via `prompts/list` and `prompts/get` (no extra install). These guide the assistant through multi-step flows; tools still execute the API calls.

| Prompt | Purpose |
|--------|---------|
| `checkout_safe_flow` | Cart → `preview_checkout` → `checkout` with required IDs |
| `attribute_full_setup` | Definition, values, assignment (AttributesHub + ProductHub quirks) |

Optional arguments personalize context (e.g. `checkout_safe_flow` with `customer_id`, `cart_id`). Cursor **skills** remain recommended for day-to-day use; prompts help Claude Desktop and other MCP clients without skill files.

## Signing in with B2Bware

There is no key to create or copy. Point your client at the server and it takes you through a browser sign-in.

<Steps>
  <Step title="Add the server to your client" icon="plus">
    Use `https://mcp.b2bware.com/mcp` with **no** key and **no** headers. Your client discovers on its own that the server wants you to sign in.
  </Step>
  <Step title="Sign in" icon="log-in">
    A browser window opens on B2Bware. Sign in the way you normally do.
  </Step>
  <Step title="Choose which accounts to connect" icon="check-square">
    Tick the B2Bware accounts this assistant may reach. Connect several, or one.
  </Step>
  <Step title="Approve" icon="shield">
    The window closes and the client is connected. Your password never reaches the assistant, and no long-lived key exists anywhere on your machine.
  </Step>
</Steps>

Your client needs to support MCP's OAuth flow — Cursor, Claude Desktop, Claude Code and VS Code all do. Older clients that do not will ask for a key instead; use the API key path for those.

## OAuth consumer contract

This is the public contract for a client that signs in. Internals of how B2Bware talks to itself are not part of it.

| What | Where |
| --- | --- |
| MCP endpoint | `https://mcp.b2bware.com/mcp` |
| Protected resource metadata | `/.well-known/oauth-protected-resource` on that host |
| Authorization server metadata | `/.well-known/oauth-authorization-server` |
| Admin connections UI | **Developers → MCP Server** |
| Storefront connections UI | Customer account → **MCP Server**, only if the shop has switched the feature on |
| Branded shop endpoint | `https://<shop-host>/mcp` on a hostname the storefront already serves |

Rules that do not change:

- The assistant acts as **you**. It cannot impersonate another user.
- Admin sign-in exposes the tools your own B2Bware login may already use. Today that is six read tools; the API-key path remains the full 163-tool surface until those converge.
- Storefront sign-in is **self-only**: your catalog, your orders, your cart, your addresses, your profile. Company-wide carts are not part of this contract.
- A token issued for one shop host cannot be replayed at another.
- Turning the storefront MCP switch off, deactivating a company, or removing the user revokes access. Revocation is immediate on the next call.

### Managing and revoking connections

**Developers → MCP Server** in the B2Bware admin lists everything connected: which client, which accounts, when it was last used. Revoking there takes effect on the next request — not when a token happens to expire.

Access also ends on its own, without anyone revoking anything, when the thing it depended on goes away: your B2Bware account is removed, your access to a company is withdrawn, or a company is deactivated. Nothing has to be remembered at offboarding time.

## Getting an API key

For server-to-server use, scripts, integrations, and any client without OAuth support.

<Steps>
  <Step title="Log in to B2Bware" icon="log-in">
    Go to your B2Bware admin panel.
  </Step>
  <Step title="Navigate to API settings" icon="settings">
    Go to **Settings → API → API Keys**.
  </Step>
  <Step title="Create or copy your API key" icon="key">
    Create a new API key or copy an existing one. This key works for both the REST API and the MCP Server.
  </Step>
</Steps>

Send it in the `Authorization` header:

```
URL: https://mcp.b2bware.com/mcp
Header: Authorization: Bearer YOUR_B2BWARE_API_KEY
```

<Callout kind="alert" title="Not in the URL">
`?key=…` still works until **1 November 2026** and then stops. See [Deprecations](#deprecations) — a key that has been in a URL should be rotated, not just relocated.
</Callout>

## For your customers: the storefront assistant

Separate from everything above. Buyers in your shop can connect their own AI assistant to **their own account** — their orders, their addresses, their cart — and nothing else.

- Turned **off** by default. Enable it per shop in **Developers → MCP Server**.
- **20 tools**: search the catalog at the prices that buyer actually gets, read their own and their company's order history, reorder, manage their own addresses, build a cart, preview and place an order.
- A buyer sees exactly what they see when signed in to your storefront — same roles, same company scope. A colleague's private address is not reachable; a draft product is not reachable.
- Buyers connect from their account area, and can disconnect there.
- Optionally served on **your own domain** (`https://shop.example.com/mcp`) instead of `mcp.b2bware.com`, on a hostname your storefront already answers on.

Company-wide carts shared between colleagues are not part of this yet — carts are per-buyer.

## Security

<Callout kind="alert" title="What an assistant can reach">
Whatever you can reach, and nothing more. Tools do not run with elevated rights: your roles, permissions and company scope are re-evaluated on every single call, by the same code that answers the admin panel and the storefront. There is no separate MCP permission model to keep in step.
</Callout>

- **Signing in leaves no long-lived credential on your machine.** Access tokens are short-lived and refreshed automatically; refresh tokens rotate on every use, and a reused one kills the whole chain.
- **Revocation is immediate**, from **Developers → MCP Server** — checked per request, not on token expiry.
- **Access ends by itself** when your account is removed, your company access is withdrawn, or the company is deactivated.
- **An assistant cannot act as someone else.** Authorization is refused outright while an operator is impersonating a customer, so a support session cannot be turned into a lasting grant.
- **A token works only at the endpoint it was issued for** (RFC 8707), so a token for one shop cannot be replayed against another.
- **API keys are never stored** by the MCP server — they live in memory for the session and are discarded on disconnect.
- Never commit API keys to version control. The sign-in config contains no secret and is safe to share.

## Troubleshooting

<Expandable title="Server not connecting" default-open="false">

1. Check the server status at [mcp.b2bware.com](https://mcp.b2bware.com)
2. Using an API key: verify it works with a direct REST API call first
3. Restart your AI tool after changing the configuration
4. Using `/sse`: make sure your client supports SSE. New setups should use `/mcp`

</Expandable>

<Expandable title="The sign-in window never opens" default-open="false">

Your client is probably not asking for one — most clients only start the OAuth flow if they were added **without** any `headers` block. Remove any `Authorization` header from the config and restart.

If it still does not appear, the client does not support MCP's OAuth flow. Use an API key instead.

</Expandable>

<Expandable title="It asks me to sign in again" default-open="false">

Something ended the grant rather than it merely expiring — expiry is handled silently in the background. In order of likelihood:

1. The connection was revoked in **Developers → MCP Server**
2. Your access to the account was withdrawn, or the company was deactivated
3. A refresh token was reused — usually two copies of the same client config running at once, which is treated as a compromise and ends the whole chain

The error text names the reason. Re-connecting fixes the third; the first two need someone to restore the access.

</Expandable>

<Expandable title="Tools not appearing" default-open="false">

1. Check that the config file is in the correct location for your tool
2. Verify the JSON syntax is valid (no trailing commas, correct quotes)
3. For Windsurf: use `serverUrl` instead of `url`
4. Restart the application after saving the config
5. Signed in and seeing only six tools? That is correct — see [Two ways to connect](#two-ways-to-connect)

</Expandable>

<Expandable title="Every call says I must name an account" default-open="false">

You connected more than one B2Bware account, so the assistant has to say which one each call applies to. Ask it to run `list_accounts` and then name the workspace you mean.

</Expandable>
